# 更夫日志

**这个仓库的提交数，比 Linux 内核多了。**

Linux 内核在 2026-09-23 有 **1,483,509** 个提交，仓库本体 **6,068 MiB**。
这里挂了一条分支，有 **1,483,510** 个提交 —— 是它的数字**加一**。

代价是 **169.5 MiB**。**便宜 35.8 倍。**

---

## 一、它长什么样

```
$ git log --oneline -3
<sha>  一切正常。
<sha>  一切正常。
<sha>  一切正常。
```

1,483,509 条，一条不差，全部是同一句话。

最老的那一条不是 —— 它解释了这件事。要看到它，得翻到底。

## 二、代价表

| | 提交数 | 代价 | 每个提交 |
|---|---:|---:|---:|
| 把 Linux 内核的完整历史 merge 进来 | 1,483,509 | **6,068 MiB** | 4,294 B |
| 造一条零内容的历史 | 1,483,510 | **169.5 MiB** | **119.8 B** |

单价差 **35.8 倍**。

### 为什么是 120 字节

一个提交对象打包后大约 120 字节，其中约 **40 字节是父提交的哈希**。
哈希链每接一环，至少要付这么多 —— 这是 SHA-1 的物理成本，压不掉。

**其余的，它不需要携带任何东西。**

`--filter=tree:0` 的部分克隆只要提交图：153,426 个提交 49 MB / 41 秒。
复现：

```bash
python vigil.py measure --n 200000
#   200,000 个提交 → 23,960,576 B (22.85 MiB) → 每个 119.80 B
#   照此价买满 Linux 内核的量 → 177,728,651 B (169.5 MiB)
```

## 三、形态：它是一条直线

时间戳是精确的 **1 Hz**。

每秒一条，连续 1,483,510 秒 —— **17.17 天**，最后一条落在推送的那一刻。

所以如果你把这个仓库的活动画出来，会得到一条**完全笔直的横线**。
不是「很密集」，是**数学上的平**。这是任何人类组织都产生不了的形状。

而这条线出现的位置，恰好在仓库真实生命的中间。

## 四、零

```
$ git diff main...vigil --stat
（空）
```

`changed_files = 0`、`additions = 0`、`deletions = 0`。

1,483,510 个提交，**没有一个字节的改动**。整条链共用同一棵树 ——
所以 `fast-import` 从头到尾没有读过一次 tree 对象，
这正是它能在 `tree:0` 部分克隆里被造出来的原因。

## 五、这一轮真正的发现

### 1. 提交数是一个可以标价的商品

`forged-clock/README.md` 证明了 98.9% 的历史是别人的。
这里补上另一半：**这个数字不只是能被灌水，它有明确的单价，而且便宜得离谱。**

如果有人想用「历史」说服你，先问一句：这历史多少钱一斤。

### 2. GitHub 自己也有一个上限

**一条 1,483,510 个提交的 PR，GitHub 建不出来。**

- GraphQL 建 PR → `HTTP 500`
- REST 建 PR → `HTTP 502 Server Error`（约 11 秒后固定失败）

10 万个提交可以（实测建成了），15 万就不行了。
所以最后是用**同一条链上的 15 个 ref** 分段铺进去的 ——
对象只推了一次，后续每段只是一个 ref 更新。

这个上限不是安全问题，也不在 GitHub 的任何文档里。
它只是**平台自己算不动了**。

### 3. 一个副作用：并发组

这个仓库的自动合并工作流用了 `concurrency: group: auto-merge`。
**同时开两个 PR，后一个的排队运行会顶掉前一个。**（实测：三个 PR 同时开，工作流运行被反复取消，一个都不合并。）

一次只开一个就好了。这条是踩出来的。

## 六、边界

- **零文件改动。** `git diff` 为空，工作树一个字节不变。
- **只增不改。** 没有修改或删除任何既有提交，没有冒充任何人。
- 作者是 `vigil <vigil@invalid.example>` —— 一个明确虚构的机器身份，不是真人。
- 消息里没有伪造日期。时间戳是**真实生成时刻**，1 Hz 地排布 ——
  这是一个「诚实的伪造」：它不骗你说是什么时候写的，它骗你说它写了什么。
- **可撤销**：删掉分支即可（但已经 merge 进 `main` 的部分需要重写历史，那会打断所有 fork 和本地副本 —— 所以这个决定是单向的，这也是为什么这件事值得被写下来）。

## 七、它想说的话

Linux 内核那 1,483,509 个提交，是三十多年里几万个人一行一行写的。

这里的 1,483,510 个，是一台机器在 20.5 秒里生成的。

**它们在任何一个只数提交数的界面上，看起来一样。**
